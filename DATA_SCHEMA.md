# Esquema de datos

Las tablas principales se organizan por IDs de sesión, fase, prueba, ensayo, medición y evento. Cada medición conserva UTC, protocolo, `client_id` opcional, `bytes_received` y `bytes_sent` separados, latencia, jitter, throughput, estado HTTP y error. En HTTP y TCP los bytes de transferencia representan la carga de aplicación; en UDP incluyen el pequeño encabezado de emparejamiento y la carga del datagrama. El throughput UDP queda vacío porque un RTT de eco no equivale a una prueba sostenida de transferencia. La configuración de carga y la dirección solicitadas se guardan en el JSON de la prueba. `app_settings` conserva la identidad del cliente y `result_outbox` conserva lotes pendientes de confirmación. `scenario_templates` conserva escenarios personalizados reutilizables. La migración v5 permite que `distance_m` sea nulo y agrega `distance_source`, `distance_uncertainty_m`, `target_distance_m` y `environment`: la distancia nominal del escenario nunca se presenta como medición real. El CSV académico `datos_hotspot.csv` incluye `id_escenario`, `clientes`, `distancia_m`, `rssi_dbm`, `latencia_ms`, `jitter_ms`, `velocidad_mbps`, `exito_sla`, `calidad_red` y `tipo_anomalia`; el CSV enriquecido agrega bytes enviados y recibidos. Los valores no disponibles quedan vacíos, nunca se inventan.
